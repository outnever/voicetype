<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keychain → 应用进程 | 密钥读取通过 SecItem API，受 macOS 沙箱和 Keychain 访问组保护 |
| UserDefaults → 应用进程 | 非敏感配置读写——禁止存密钥 |
| 用户输入 → SettingsView | 用户在 SecureField 输入的 API 密钥明文跨过此边界 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | KeychainStore.swift | high | mitigate | 所有 API 密钥仅通过 SecItem API 写入 macOS Keychain（`kSecClassGenericPassword` + `kSecAttrAccessibleAfterFirstUnlock`）。禁止落 UserDefaults、@AppStorage 及任何 plist 文件。code review 扫描 `UserDefaults.standard.set` 旁出现 "key" / "api" / "token" 字符串。 |
| T-01-02 | Information Disclosure | SettingsView.swift | medium | mitigate | API 密钥设置界面默认脱敏显示（`••••` + 末4位）。SecureField 禁止自动纠错/自动大写（`.textContentType(.password)`）。设置窗口关闭时立即清除内存中的明文输入。 |
| T-01-03 | Tampering | KeychainStore.swift | medium | mitigate | 所有 `SecItemAdd` / `SecItemCopyMatching` / `SecItemDelete` 的 `OSStatus` 返回值显式检查。`errSecDuplicateItem` 时先删除后重新添加。`errSecItemNotFound` 时抛出明确错误而非无声失败。 |
| T-01-04 | Elevation of Privilege | PermissionManager.swift | medium | mitigate | 权限请求前给出清晰的中文说明 WHY 需要该权限（D-07）。不自动打开系统设置——用户主动点击按钮后才跳转。权限状态始终在菜单栏图标可见（D-08）。 |
| T-01-05 | Denial of Service | AppCoordinator.swift | low | accept | 启动时所有重操作（权限检查）在 `Task.detached(priority: .userInitiated)` 异步执行。菜单栏图标在 init 中立即设置默认值（SHEL-01）。即使权限检查失败，应用仍可显示菜单栏并给出错误提示。风险低——无网络依赖，仅本地 API 调用。 |
| T-01-SC | Tampering | SPM packages (WhisperKit, MacPaw/OpenAI, swift-log) | high | mitigate | 所有 SPM 依赖已验证：WhisperKit (6.3k stars, argmaxinc/argmax-oss-swift), MacPaw/OpenAI (2.9k stars), swift-log (Apple 官方)。Package Legitimacy Audit 全部通过，无 [SLOP] 或 [SUS] 判定。依赖版本已锁定。 |
</threat_model>
