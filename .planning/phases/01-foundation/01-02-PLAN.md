  <files>VoiceType/Hotkeys/HotkeyManager.swift, VoiceType/Hotkeys/HotkeyConfiguration.swift</files>
  <action>
实现基于 CGEvent.tapCreate 的系统级全局热键管理系统（per D-03 Fn hold-to-talk, D-04 Ctrl+Shift+C press-to-trigger, D-05 CGEvent.tapCreate 不用 Carbon, RESEARCH.md Pattern 4）：

1. **HotkeyConfiguration.swift：**
   ```swift
   enum HotkeyMode {
     case holdToTalk    // 按住触发，松开停止（听写）
     case pressToTrigger // 按一下触发（纠错）
   }

   struct HotkeyDefinition {
     let keyCode: Int64
     let modifiers: CGEventFlags
     let mode: HotkeyMode
     let description: String
   }

   enum HotkeyDefaults {
     static let dictation = HotkeyDefinition(
       keyCode: 63,  // kVK_Function (Fn key)
       modifiers: [], // Fn key 通过 flagsChanged 事件处理
       mode: .holdToTalk,
       description: "Fn (hold to talk)"
     )
     static let correction = HotkeyDefinition(
       keyCode: 8,   // kVK_ANSI_C
       modifiers: [.maskControl, .maskShift],
       mode: .pressToTrigger,
       description: "Ctrl+Shift+C (press to correct)"
     )
   }
   ```
   - 定义热键错误枚举 `enum HotkeyError: Error`

2. **HotkeyManager.swift（per RESEARCH.md Pattern 4 完整实现）：**
   - `final class HotkeyManager: @unchecked Sendable`
   - 属性：`private var eventTap: CFMachPort?`、`private var runLoopSource: CFRunLoopSource?`、`private var tapThread: Thread?`、`private let dictationKeyCode: Int64 = 63`、`private let correctionKeyCode: Int64 = 8`
   - Fn 键状态跟踪：`private var isFnKeyDown: Bool = false`（因为 Fn 键通过 `.flagsChanged` 而非 `.keyDown/.keyUp` 发送事件）

3. **`func register() throws`：**
   - 事件掩码：`CGEventMask((1 << CGEventType.keyDown.rawValue) | (1 << CGEventType.keyUp.rawValue) | (1 << CGEventType.flagsChanged.rawValue))`
   - `CGEvent.tapCreate(tap: .cgSessionEventTap, place: .headInsertEventTap, options: .defaultTap, eventsOfInterest: eventMask, callback: eventTapCallback, userInfo: UnsafeMutableRawPointer(Unmanaged.passUnretained(self).toOpaque()))`
   - 创建专用 RunLoop 线程（`Thread { ... CFRunLoopRun() }`），线程名 `com.voicetype.hotkey-tap`
   - 将 CFMachPort 创建 CFRunLoopSource 并添加到当前 RunLoop 的 `.commonModes`
   - `CGEvent.tapEnable(tap: tap, enable: true)`
   - 返回前确认 `CGEvent.tapIsEnabled(tap: tap) == true`，否则抛出 `HotkeyError.tapCreationFailed`

4. **C 回调函数 `eventTapCallback`：**
   - 通过 `Unmanaged<HotkeyManager>.fromOpaque(userInfo!).takeUnretainedValue()` 取回 manager 引用
   - `.keyDown` / `.keyUp` → 读 `event.getIntegerValueField(.keyboardEventKeycode)` 和 `event.flags`，调用 `manager.handleKeyEvent(keyCode:flags:isKeyDown:)`
   - `.flagsChanged` → 处理 Fn 键（keyCode 63），读 `event.flags.contains(.maskSecondaryFn)` 判断按下/释放
   - `.tapDisabledByTimeout` / `.tapDisabledByUserInput` → 尝试 `CGEvent.tapEnable(tap: tap, enable: true)` 恢复
   - **关键：** 回调返回 `Unmanaged.passUnretained(event)`（不消费事件）→ 热键事件正常传递给系统和其他应用

5. **`func handleKeyEvent(keyCode:flags:isKeyDown:)`：**
   - **Dictation (Fn hold-to-talk per D-03)：** Fn 键通过 flagsChanged 处理，维护 `isFnKeyDown` 状态
     - 检测到 Fn 按下（flagsChanged + maskSecondaryFn 出现）→ 通过 `coordinator?.onDictationKeyDown?()` 通知
     - 检测到 Fn 释放（flagsChanged + maskSecondaryFn 消失）→ 通过 `coordinator?.onDictationKeyUp?()` 通知
     - **Edge case:** 如果同时按下 Fn + 其他键（如 Fn+F1），忽略——只处理纯 Fn 按下/释放
   - **Correction (Ctrl+Shift+C press-to-trigger per D-04)：** keyDown 时检测 keyCode==8 且 flags 同时包含 `.maskControl` 和 `.maskShift`
     - 检测到 → 通过 `coordinator?.onCorrectionKeyPress?()` 通知
     - **注意：** correction 是 press-to-trigger，fire 后标记 `correctionFiredInCurrentCycle = true`，直到所有 modifier 都 keyUp 后才重置——防止一次按键触发多次

6. **回调钩子注入：**
   - `weak var coordinator: AppCoordinator?` —— Plan 01-01 的 AppCoordinator 创建 HotkeyManager 时设置此引用
   - 所有回调通过 `DispatchQueue.main.async { self.coordinator?.onXxx?() }` 回到主线程（CGEvent 回调在专用线程）

7. **编译验证：** Build 成功。`HotkeyManager.register()` 可被调用（此时 coordinator 回调未设置，热键事件仅记录日志不崩溃）。

  <name>Task 2: 实现 Watchdog 权限监控与 AppCoordinator 集成</name>
  <files>VoiceType/Hotkeys/HotkeyManager.swift</files>
  <action>
实现热键 tap 运行时健康监控（per D-06 watchdog, RESEARCH.md Pitfall 1 预防, HOTK-04）：

1. **Watchdog 计时器（per RESEARCH.md Pitfall 1 完整方案）：**
   - `func startWatchdog(interval: TimeInterval = 5.0)` —— 每 5 秒检查 `CGEvent.tapIsEnabled(tap: eventTap)`
   - 如果 tap 失活 → 尝试 `CGEvent.tapEnable(tap: tap, enable: true)` 恢复
   - 如果恢复失败（tap 仍为 disabled）→ `DispatchQueue.main.async` 发送 `NotificationCenter.default.post(name: .hotkeyTapDisabled, object: nil)`
   - AppCoordinator 监听 `Notification.Name.hotkeyTapDisabled` → 更新 `statusMessage` 为 "热键权限丢失——请重新授予辅助功能权限"，菜单栏图标变橙色/红色

2. **事件心跳检测（额外安全层）：**
   - `private var lastEventTimestamp: Date = Date()`
   - 每次事件回调中更新 `lastEventTimestamp`
   - Watchdog 中增加检查：如果 `Date().timeIntervalSince(lastEventTimestamp) > 30` 且 tap 显示为 enabled → tap 可能无声故障，尝试重新启用并通知

3. **AppCoordinator 集成（修改 AppCoordinator.swift）：**
   - 在 AppCoordinator 中添加 `let hotkeyManager = HotkeyManager()` 实例
   - 在异步初始化块中设置回调钩子：
     ```
     hotkeyManager.onDictationKeyDown = { [weak self] in self?.state = .recording }
     hotkeyManager.onDictationKeyUp = { [weak self] in self?.state = .idle }
     hotkeyManager.onCorrectionKeyPress = { [weak self] in self?.state = .correcting }
     ```
   - 添加 `@Published var hotkeyTapActive: Bool = false`
   - 监听 `Notification.Name.hotkeyTapDisabled` → 设置 `hotkeyTapActive = false` 并更新 `statusMessage`
   - 注册成功后设置 `hotkeyTapActive = true`
   - **关键：** 在 Coordinator 初始化后调用 `try? hotkeyManager.register()` + `hotkeyManager.startWatchdog()`

4. **扩展 Notification.Name：**
   在 HotkeyManager.swift 或 AppCoordinator.swift 中定义：
   ```swift
   extension Notification.Name {
     static let hotkeyTapDisabled = Notification.Name("com.voicetype.hotkey.tapDisabled")
   }
   ```

5. **编译验证：** Build 成功。模拟权限丢失场景（后续通过 `tccutil reset Accessibility` 测试）。

6. **注意——禁止在 HotkeyManager 中硬编码回调逻辑：** HotkeyManager 仅负责检测事件并通过回调/通知传递，不自行切换 AppState。所有状态变更在 AppCoordinator 中统一完成（per ARCHITECTURE.md 子系统隔离原则）。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 系统键盘事件 → CGEvent tap | 所有应用的键盘事件通过 CGEvent tap 进入回调——不应消费事件，仅观察 |
| HotkeyManager 专用线程 → AppCoordinator (MainActor) | 热键事件从实时 RunLoop 线程跨线程传递到 UI 线程 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Denial of Service | HotkeyManager.swift | high | mitigate | CGEvent tap 被系统禁用时（OS 更新、权限撤销），5 秒 watchdog 检测到失活 → 自动尝试 `CGEvent.tapEnable` 恢复 → 失败则发通知并在菜单栏图标显示警告（HOTK-04, D-06）。事件心跳监控补充：30 秒无事件即使 tap 显示 enabled 也触发告警（PITFALLS.md Pitfall 1）。 |
| T-01-07 | Elevation of Privilege | HotkeyManager.swift | medium | mitigate | 热键事件回调仅观察（返回 `Unmanaged.passUnretained(event)`），不消费或修改事件。Fn 键的 flagsChanged 特殊处理：仅检测 `.maskSecondaryFn` 标志，不拦截系统级 Fn 行为（Touch Bar 切换、亮度调节等）。所有事件通过 `DispatchQueue.main.async` 回主线程前不做阻塞操作。 |
| T-01-08 | Information Disclosure | HotkeyManager.swift | low | accept | CGEvent tap 可观察所有应用的按键事件（包括密码字段按键）。设计约束：HotkeyManager 仅检测特定键码（63 和 8 + 修饰键），不记录其他按键。回调中仅做键码比较，不存储或转发按键内容。tap 的 `.headInsertEventTap` 位置不阻止事件传递。风险低——系统级键盘监控工具在接入 Accessibility 权限后本就可以做到这一点，且此风险在接受范围内（所有获取 Accessibility 权限的应用均有此能力）。 |
| T-01-09 | Tampering | HotkeyManager.swift | low | accept | 回调函数指针 `Unmanaged.passUnretained(self).toOpaque()` 传递原始指针——若 HotkeyManager 在 tap 注册后被释放，回调将访问野指针导致崩溃。缓解：HotkeyManager 生命周期由 AppCoordinator 管理（Coordinator 存活期间 HotkeyManager 不释放）。风险低——应用架构保证 Coordinator 不提前释放。 |
</threat_model>
