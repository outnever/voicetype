<objective>
Deliver cross-application text insertion: a protocol-based TextIO layer with `AccessibilityBridge` (AXUIElement primary strategy) and `ClipboardBridge` (NSPasteboard fallback), composed via `CompositeTextIO`. When transcription completes, text appears at the cursor in any app — or the clipboard fallback transparently takes over.

Purpose: The "last mile" of dictation. Without this, transcription output stays trapped in memory. This is also the highest-risk subsystem — AXUIElement compatibility varies dramatically across apps (PITFALLS.md §1), and clipboard corruption destroys user trust (PITFALLS.md §5).

Output: `VoiceType/TextIO/` directory with four files: `TextIOProtocol.swift` (contract), `AccessibilityBridge.swift` (AX primary), `ClipboardBridge.swift` (pasteboard fallback), `TextInsertionError.swift` (typed errors).
</objective>

**2. TextInsertionError.swift** — typed errors:
- `noFocusedApp` — no app has system focus
- `noFocusedElement` — focused app has no accessible text element
- `axWriteFailed(code: Int32)` — `AXUIElementSetAttributeValue` returned non-success
- `passwordFieldBlocked` — target is a secure text field (D-10)
- `clipboardRestoreFailed` — could not restore original clipboard content
- `allStrategiesFailed` — both AX and clipboard fallback exhausted
- All conform to `Error, LocalizedError` with Chinese descriptions — e.g. "无法定位当前输入框——请确认目标应用已获得焦点并支持辅助功能文字输入"

**3. AccessibilityBridge.swift** — primary text insertion strategy (D-08, D-10):
- `import ApplicationServices`
- `final class AccessibilityBridge: TextIOProtocol`
- `func insertText(_ text: String) async throws`:
  1. `AXUIElementCreateSystemWide()` → get `kAXFocusedApplicationAttribute`
  2. If no focused app → throw `.noFocusedApp`
  3. From focused app → get `kAXFocusedUIElementAttribute`
  4. If no focused element → throw `.noFocusedElement`
  5. `AXUIElementSetAttributeValue(axElement, kAXSelectedTextAttribute as CFString, text as CFTypeRef)`
  6. Check return code: `.success` → done; else → throw `.axWriteFailed(code:)`
- `func isPasswordField() -> Bool`:
  1. Same focused-app → focused-element resolution as above
  2. `AXUIElementCopyAttributeValue(element, kAXIsPasswordFieldAttribute, &isPassword)`
  3. Return `(isPassword as? Bool) ?? false`
- **Key design decisions:**
  - Uses `kAXSelectedTextAttribute` (not `kAXValueAttribute`) — when user has no selection, this inserts at cursor as dictated by AX spec
  - All AX calls are synchronous — no need for async wrapping, but method is `async throws` for protocol consistency with ClipboardBridge
  - Does NOT read text from target app — write-only (privacy + PITFALLS.md Access Control section)
- **PITFALLS.md §1 awareness:** AXUIElement is known to fail on Electron apps, terminal emulators, and some custom-drawn UIs. This bridge should fail GRACEFULLY (throw typed error) — CompositeTextIO (Task 2) handles the fallback. Do NOT add per-app workarounds or app-specific logic; keep it pure.

**PITFALLS.md §1, §5 integration note:** This task only creates the primary strategy. The fallback chain (CompositeTextIO) is created in Task 2. Task 1's AccessibilityBridge should be independently testable against AppKit apps.

**1. ClipboardBridge.swift** — clipboard fallback strategy (D-09, D-19, PITFALLS.md §5):
- `import AppKit` (NSPasteboard)
- `import CoreGraphics` (CGEvent for key simulation)
- `final class ClipboardBridge: TextIOProtocol`
- `func insertText(_ text: String) async throws`:
  - **Step 1 — Save:** Read original clipboard: `let originalString = NSPasteboard.general.string(forType: .string)`
  - **Step 2 — Write:** `NSPasteboard.general.clearContents()` then `NSPasteboard.general.setString(text, forType: .string)`
  - **Step 3 — Wait:** `try await Task.sleep(nanoseconds: 100_000_000)` // 100ms — ensure clipboard write completes (PITFALLS.md §5)
  - **Step 4 — Paste:** `simulateCommandV()` — CGEvent post Cmd key (0x37) + V key (0x09) with `.maskCommand` flags, using `.cghidEventTap`
  - **Step 5 — Wait:** `try await Task.sleep(nanoseconds: 200_000_000)` // 200ms — allow paste to complete in target app
  - **Step 6 — Restore:** `NSPasteboard.general.clearContents()` then restore `originalString` if non-nil
- `private func simulateCommandV()`: Uses `CGEventSource(stateID: .combinedSessionState)` to create and post Cmd-down, V-down, V-up, Cmd-up events to `.cghidEventTap`
- `func isPasswordField() -> Bool` — always returns `false` (ClipboardBridge does NOT read the target app; password check is done upstream by AccessibilityBridge)
- **PITFALLS.md §5:** The save→write→paste→restore cycle with explicit timing delays is the CRITICAL path. Without the 100ms write delay + 200ms paste delay, paste events fire before clipboard population completes or restore happens before the paste resolves.

**2. CompositeTextIO** — fallback chain (per RESEARCH.md Pattern 2):
- Add `CompositeTextIO` class in `AccessibilityBridge.swift` (or a separate file — agent discretion):
```swift
final class CompositeTextIO: TextIOProtocol {
    let primary: AccessibilityBridge
    let fallback: ClipboardBridge

    init(primary: AccessibilityBridge, fallback: ClipboardBridge) {
        self.primary = primary
        self.fallback = fallback
    }

    func insertText(_ text: String) async throws {
        // D-10: Check password field before any insertion attempt
        guard !primary.isPasswordField() else {
            Log.textIO.warning("Password field detected — refusing to insert text")
            throw TextInsertionError.passwordFieldBlocked
        }

        // D-08: Primary strategy — AXUIElement
        do {
            try await primary.insertText(text)
            return
        } catch {
            Log.textIO.warning("AXUIElement insert failed: \(error). Falling back to clipboard.")
        }

        // D-09, D-19: Fallback strategy — Clipboard
        do {
            try await fallback.insertText(text)
        } catch {
            Log.textIO.error("All text insertion strategies failed: \(error)")
            throw TextInsertionError.allStrategiesFailed
        }
    }

    func isPasswordField() -> Bool { primary.isPasswordField() }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VoiceType Process → Target App (AX) | AXUIElement writes cross process boundaries via macOS accessibility framework — text is injected into foreign application memory |
| VoiceType Process → System Clipboard | NSPasteboard is a shared system resource — any process can read/write simultaneously |
| VoiceType → CGEvent Stream | Simulated Cmd+V key events are indistinguishable from real keystrokes to the target app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Information Disclosure | AccessibilityBridge | high | mitigate | Password field detection via `kAXIsPasswordFieldAttribute`: `isPasswordField()` check at CompositeTextIO level BEFORE any insertion attempt (D-10). If detected, throw `.passwordFieldBlocked` — neither bridge is invoked. This prevents dictation text from appearing in password/secure fields. |
| T-02-07 | Information Disclosure | ClipboardBridge | medium | mitigate | Clipboard save-and-restore cycle: original content read before write, restored after paste with 200ms delay. Transcribed text exists on clipboard for ~300ms window — this is an accepted, minimal exposure. If restore fails, the clipboard is left clean (cleared) rather than corrupted with stale dictation text. |
| T-02-08 | Tampering | ClipboardBridge | medium | mitigate | CGEvent-simulated Cmd+V could be intercepted by other apps (clipboard managers, macro tools). This is inherent to pasteboard-based text transfer — the target app has no way to distinguish our paste from a user-initiated one. Mitigated by using AXUIElement as primary strategy (D-08); clipboard is fallback only. |
| T-02-09 | Elevation of Privilege | AccessibilityBridge | low | accept | AXUIElement text insertion requires accessibility permission — already granted by user in Phase 1. The app only writes, never reads (privacy-preserving by design). Risk of misuse (writing to unintended fields) is accepted — the user explicitly initiated dictation via hotkey and expects text at cursor. |
| T-02-10 | Denial of Service | ClipboardBridge | low | accept | If clipboard is locked by another process during the 300ms window, `setString` or `clearContents` could fail. Accept — this is a rare race condition; the fallback chain returns `.allStrategiesFailed` and the user can retry dictation. |
</threat_model>
